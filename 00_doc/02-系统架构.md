# 系统架构

> 整机是**基于 openvela 的作品**（内核 openvela / NuttX）。用到了 openvela 的图形框架、
> 蓝牙框架 + zblue 主机栈、KVDB 等；板级差异走 `vela_override/` 抽换机制、不改上游。
> 详见 [08-openvela与参赛.md](08-openvela与参赛.md)。

## 仓库布局

| 目录 | 内容 | 形态 |
|---|---|---|
| `00_doc/` | 本目录，产品与工程文档 | 普通目录 |
| `01_hw/` | 硬件设计（Altium `.epro2`） | 普通目录 |
| `02_sw/` | 车机固件 + 台架传感器模拟器 | 固件是 **git submodule** |
| `03_app/` | 手机 App（Flutter） | 普通目录 |
| `04_tools/` | PC 端工具链（当前主要是地图） | 普通目录 |

### `02_sw` 的两块

```
02_sw/
├── vendor/vela_sifli/     ← 车机固件。git submodule，指向 gitee 的固件仓库
└── esp32/                 ← 台架用的三个 BLE 传感器模拟器（ESP32-S3）
    ├── hrs_sim/           ← 冒充心率带（GATT 0x180D）
    ├── csc_sim/           ← 冒充踏频计（GATT 0x1816）
    └── cps_sim/           ← 冒充功率计（GATT 0x1818）
```

固件为什么用 submodule、日常该在哪边改，见 [07-仓库维护.md](07-仓库维护.md)。

ESP32 模拟器的用途：在没有真传感器（或真传感器不好使）时，把车机"扫描 → 绑定 → 订阅 → 显示"
整条链路跑通。三个工程各自独立编译，地址和广播名固定，车机侧用 `ctl sensor bind` 绑。
详见 `02_sw/esp32/README.md`。

## 两条数据流

**第一条：骑行数据**

```
心率带 / 踏频计 / 功率计
        │ BLE notify
        ▼
车机 BLE Central  ──►  骑行状态  ──►  界面五页
        │                              │
        │                              ▼
        │                         轨迹记录（SD 卡）
        ▼
   BLE 通知 App（实时镜像）
```

**第二条：地图**

```
OpenStreetMap（.osm.pbf）
        │  04_tools/vmap：切片 + 路网 + 高程
        ▼
设备地图包（lon*/lat*/x*_y*.vpk，3 km 网格）
        │  拷进固件树 mkfs/fat/map/ → 打包成 SD 镜像
        ▼
SD 卡  ──►  车机读取、矢量渲染 + 离线算路
```

工具链怎么跑见 [05-地图工具链.md](05-地图工具链.md)。
