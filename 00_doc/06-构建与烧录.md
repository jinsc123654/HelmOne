# 构建与烧录

## 前提：固件要在 openvela SDK 里编

**这一条最容易踩**：`02_sw/vendor/vela_sifli/` 是**源码**，单独克隆出来**编不了**。
NuttX 本体、构建系统、工具链都在 openvela SDK 那棵树里，固件仓库是以
`vendor/my_vendor` 的身份挂在 SDK 下面的。

证据在代码里：`build_board.py` 要 `_VENDOR_ROOT.parent.parent` 下能找到工具实现，
`make_sd_img.sh` 直接算 `ROOT="$(cd "$HERE/../.." && pwd)"` 当"openvela 工作区根"
再调 `$ROOT/vendor/my_vendor/build_board.py`。

所以完整的构建环境长这样：

```
openvela/                      ← SDK 工作区根（含 build.sh、nuttx/）
└── vendor/
    └── my_vendor/             ← 固件源码，就是本仓库的 02_sw/vendor/vela_sifli
```

本仓库的 submodule 和 SDK 里那份是**同一个 gitee 仓库的两处 checkout**，
靠 commit 对齐。日常在 SDK 那边改和编，改完 push，回本仓库把 submodule 指针跟上
（见 [07-仓库维护.md](07-仓库维护.md)）。

## 编译 + 烧录 + 看串口

**都在 openvela 根目录执行**：

```bash
# 日常：编固件 + 烧录 + 串口监视（不含 NAND 文件系统）
python3 vendor/my_vendor/build_board.py build flash monitor

# 首次或全量：再加 bicycle 资源分区
python3 vendor/my_vendor/build_board.py build-all flash-all monitor
```

子命令可以**组合**，按书写顺序依次执行。常用的：

| 命令 | 作用 |
|---|---|
| `build` | 编译 NuttX；按需自动 `build-boot` / `build-fs` / `wrap` |
| `build-boot` | 只构建 `ftab.bin` + `bootloader.bin` → `boot_loader/bin/` |
| `build-factory` | 编译工厂变体 |
| `build-fs` | 打包 NAND LittleFS → `fs_root.bin` |
| `flash` | 烧 ftab + bootloader + nuttx（**不含**文件系统和 factory） |
| `flash-all` | 烧 `sftool_param.json` 里的全部条目 |
| `menuconfig` / `savedefconfig` | 配置 / 把配置写回 defconfig |

产物位置：

| 东西 | 路径 |
|---|---|
| NuttX 输出 | `cmake_out/my_vendor_nsh/` |
| 烧录快照（类似 IDF 的 flasher_args） | `cmake_out/my_vendor_nsh/flasher_args.json` |
| Boot 镜像 | `vendor/my_vendor/boot_loader/bin/` |
| 烧录清单 | `vendor/my_vendor/boot_loader/config/nsh/sftool_param.json` |
| 分区地址 | `boot_loader/config/nsh/ptab.json` |

命令的**全量说明**在固件仓库的 `docs/tools/vela_my_vendor_tools.md`；
**调试现场口径**（串口归属、读崩溃、看屏幕）在同目录的 `debug_workflow.md`。

## 做 SD 整盘镜像

```bash
cd <openvela>
./vendor/my_vendor/make_sd_img.sh 16G            # 输出到 boot_loader/bin/my_vendor_sd.img
./vendor/my_vendor/make_sd_img.sh 16G -o /tmp/x.img
```

它一条命令做四件事：编 main 槽固件 → 编 factory 槽固件 → 重建二级 boot → 打包成整盘 `.img`
（逻辑大小 = 你给的卡容量）。**只出镜像，不烧录**。

固件树里还有几个按容量写好的薄包装，等价于上面这条：

```bash
./docs/tools/make_sd_2g.sh      # 也有 4g / 8g / 16g
```

> 分区表是按 ~15 GiB 布局的，**卡容量小于 16G 会被拒绝**。

## 单独编二级 bootloader

```bash
cd vendor/my_vendor/boot_loader
./build.sh                       # → bin/{ftab.bin, bootloader.bin}
./build.sh --bootloader-only
SIFLI_SDK=/path/to/SDK/2.4 ./build.sh
BOOT_STORAGE=sd ./build.sh       # 选择默认启动介质（nand/sd/emmc/nor）
```

默认启动介质也可以写死在 `boot_loader/storage.conf` 里。

## 地图


然后重打一次 SD 镜像。详见 [05-地图工具链.md](05-地图工具链.md)。

## 台架传感器模拟器

三个 ESP32-S3 工程各自独立：

```bash
cd 02_sw/esp32/csc_sim           # 或 cps_sim / hrs_sim
source ~/ESP_IDF/5.4.3/esp-idf/export.sh
idf.py build flash monitor
```

地址和广播名是固定的，车机侧用 `ctl sensor bind` 绑。详见
`02_sw/esp32/README.md`。

## 检查清单

- [ ] 固件放在 `<openvela>/vendor/my_vendor`（不是随便放）
- [ ] 二级 boot 编过（`boot_loader/bin/` 里有两个 `.bin`），否则用随仓的旧 bin
- [ ] 地图包已拷进 `mkfs/fat/map/`，并重打了 SD 镜像
- [ ] 烧的是 `flash-all` 而不是 `flash`（后者不带文件系统和 factory）
